Every run is kept: its reports, screenshots, and the complete conversation.
The **Runs** page is where you open them.

## Open a run's results

1. Open the **Runs** page.
2. Pick the run in the sidebar, newest first, one entry per run with its
   pass tally. The icon before the name says what the run executed: the
   **Test Plans** icon for a test plan, the **Tests** icon for a test or a
   folder, the same icons as in the left navigation.
3. Choose what to look at:
   - **Conversation log**: the full execution record (below).
   - **Summary report**: the run-level table, one row per test.
   - **The per-test entries**: each test's
     [test report](/docs/results/run-report) with its status badge.

**Open in Explorer** on a test jumps to its files on disk, the run's folder
is one level up.

## Run it again

Right-click a run in the sidebar:

- **Rerun all** starts the same thing again. A test plan run runs the plan
  again, on the devices the plan names now; a test or folder run runs the
  same test or folder on the device the run used.
- **Rerun failed** starts only the tests of that run whose result was
  FAILED or BROKEN, one run per test, on the device the run used, queued
  one after the other. It is greyed out, with the reason, when nothing
  failed or when none of the failed tests' files can be found.

Right-click a test under the selected run for **Rerun this test**: only that
test, on the device the run used, whether the run was a test plan or not.

A rerun starts exactly like a first run: if the device is busy you are asked
whether to queue it, see [Running tests](/docs/running-tests). Several
failed tests that cannot start right away are queued with one answer.

When the app cannot tell which device the run used, because the run is from
before the app recorded it or that device has since been deleted, a picker
asks you to choose one. A rerun never picks a device for you. Runs from
before the app recorded their target can be rerun as a whole only when they
ran a single test whose file still exists; otherwise **Rerun all** is greyed
out and says why.

## Open the test in the editor

Each test under a run has a pencil at the right of its row, and **Open in
editor** in its right-click menu. Either opens that test's file on the
**Tests** page, so a failed test is one click from its fix. Both are
disabled when no file is known for the row: a setup or teardown entry, a
test file that was renamed or removed since the run, or an older run whose
test name matches two files.

## Conversation log

Beside the written reports, every run keeps its full conversation, each
agent message, tool call, and screenshot in order. Where the report gives
the result, the log is the complete execution record: open it when a status
alone doesn't explain what happened.

## Share results

To hand a result to a developer or attach it to a ticket, zip the run's
timestamped folder (**Open in Explorer** on a test, one level up), the
reports are plain Markdown with the step screenshots next to them, readable
anywhere.

## On disk

Each run is one timestamped folder under `agent_workspace/`:

```
<project>/agent_workspace/
└── 2026-07-23_21-56-55/          ← one folder per run
    ├── conversation.json          ← the conversation (the app re-renders it)
    ├── summary_report.md          ← run-level table
    └── open_notepad_windows/      ← one folder per test
        ├── open_notepad_windows_report.md   ← the test report
        ├── step_1.png
        └── step_2.png
```

Run folders are independent of each other, archive or delete old ones as
your evidence-retention policy requires; the Runs list and
[Dashboard](/docs/results/dashboard) reflect whatever folders exist. The
folder is [gitignored](/docs/projects#git-versioning--sync) by design. From
the CLI, `--workspace` overrides the location.
