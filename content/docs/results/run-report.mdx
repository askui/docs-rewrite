A run records three things: the **result** of each test, an **execution
report** per test, and the run-level **summary report**. Where they live and
how to open them: [Runs](/docs/results).

## Test result

The agent ends each test by recording its result: one status and a short
reason, for example `FAILED`, "Expected the dashboard, saw an error
banner.". The recorded result decides whether the test passed. The summary
report, the Dashboard, and the [Management Report](/docs/results/management-report)
all count it.

The agent picks the status by AskUI's
[status definitions](/docs/extending/reporting#status-definitions). The
status is one of `PASSED`, `WARNING`, `FAILED`, `SKIPPED`, `UNCLEAR`,
`BROKEN`, or `BLOCKED`. What each one means, which are conclusive, and how
they count: [Test statuses](/docs/results/test-statuses).

The reason names what was expected and what was observed. A test that ends
normally without a recorded result is `UNCLEAR`, with the reason "The
test ended without recording a result.". A test that crashes before it
recorded anything is `BROKEN`, with the error as the reason. If the agent
records more than once, the last result counts. The result is saved next to
the test as `<test_name>_result.json`.

### Tests that never finished

A test the run never finished is `BLOCKED`, never `SKIPPED`. Its note in the
summary report names the reason:

| Note | When |
| --- | --- |
| Not run: a setup it depends on failed. | A [setup](/docs/writing-tests/setup-teardown-rules#how-a-setup-or-teardown-ends) of its folder ended `FAILED`, `UNCLEAR`, or `BROKEN`, or it crashed. |
| Not run: `<test>` broke the run before this test. | An earlier test crashed, and the run ended there. |
| Not run: the operator stopped the run before this test. | You stopped the run before this test started. |
| The run was stopped during this test. | You stopped the run while this test ran. |
| Not run: the run failed before this test. | The runner failed before this test started. |
| The run ended during this test. | The runner failed while this test ran. |

A `BLOCKED` test is not conclusive: it lowers the conclusive share, never
the pass rate.

A setup that records `SKIPPED` is different: what it prepares is not
available, so its tests are `SKIPPED`, with the setup's reason, or with
"Not run: a setup it depends on found what it prepares not available." when
it gave none. They are conclusive.

For runs from older versions, the app shows a test that the summary listed
as broken without a duration as `SKIPPED`.

## Execution report

The execution report is the written record of one test: what the agent did,
what it expected, and what it observed, with screenshots. The agent that ran
the test does not write it. A separate agent writes it after the test ends:
it reads the test's conversation and screenshots and follows your project's
[report format](/docs/extending/reporting#report-format). The next test
starts at once, so a report never slows a run down.

Whether a test gets a report, and which model writes it, you set under
[Extending → Reporting](/docs/extending/reporting). A test without a report
can get one later from the **Runs** page:
[Write a report later](/docs/results#write-a-report-later).

Section by section:

- **Test metadata**: who, when, and how it went.
  - **Test Case ID**: ties the report to the
    [test case](/docs/writing-tests), its title ID or file name.
  - **Date**: when the test executed.
  - **Status**: the [result the test recorded](#test-result). The report
    states it as given and cannot change it.
  - **Cost of this test**: right behind the status. The test's execution
    cost comes first, and the total including this report follows in
    parentheses, for example `$0.33 ($0.41 with reporting)`, in whole cents. When only
    the report's cost is known, it reads `$0.08 for the report`. Without
    a known price, the cost is left out. The cost also adds to the run's
    total, which the summary report in the app shows as
    **Cost of this run:**.
- **Summary**: the outcome in two sentences, read this first.
- **Preconditions**: whether the assumed starting state was actually met,
  a test that began from the wrong state fails here, not misleadingly in a
  step.
- **Test Steps**: one entry per step.
  - **Agent Interpretation**: how the agent understood your instruction,
    check this when a step surprises you.
  - **Expected** / **Actual**: the step's contract and what was actually
    observed.
  - **Status**: the step's own status: `PASSED`, `WARNING`, `FAILED`,
    `SKIPPED`, `UNCLEAR`, or `BROKEN`.
  - **Screenshot**: the step's evidence, exactly one per step: the
    screenshot that shows the step's outcome. A second one appears only as
    a rare exception, for example to compare before and after. This holds
    whatever your report format says. The writer picks the screenshot from
    those the agent took during the test, so the numbers in the file names
    (`screenshot_<n>.png`) need not run in order.
- **Postconditions**: whether the overall pass criterion held at the end.
- **Issues**: anything worth a look that isn't a failure, the incident
  notes. In the example above: the 15-second sign-in.
- **Conclusion**: the closing assessment of the whole case.

The report's shape is defined by your project's
[report format](/docs/extending/reporting#report-format). To share a report
with someone without the app, export it as PDF, JSON, or JUnit XML:
[Export](/docs/results/export). What to do with a failing report, triage,
root cause, where the fix belongs:
[Analyzing failures](/docs/best-practices/analyzing-failures).

### Files of a test

Each test has its own folder in the run folder:

| File | Holds |
| --- | --- |
| `<test_name>_result.json` | The recorded result: status, reason, start and end time. |
| `<test_name>_report.md` | The execution report. |
| `screenshot_<n>.png` | The screenshots the report embeds. |
| `<test_name>_report.json` | The report's state (`ready` or `failed`, with the error), the model, the tokens, and the cost. |

---

## Summary report

`summary_report.md` in the run folder summarizes the whole run: a totals head,
one Markdown table across all tests with status and execution time per test,
and detail sections that quote the recorded reason of every test that did
not end `PASSED`.

The totals head holds the test-case count, the pass rate and the conclusive
share, one count per status that occurred, and the run duration. The detail
sections follow the table in this order: **⚠️ Warnings**, **❌ Fails**,
**❔ Unclear**, **💥 Broken**, **⛔ Blocked**, and **⏭️ Skipped**. A
section appears only when a test ended with its status.

```markdown
# Summary Report

**Date:** 2026-11-21

**Total:** 4 Test Cases
- **Pass rate:** 50 % · **Conclusive:** 3/4 (75 %)
- **✅ Passed:** 1
- **❌ Failed:** 1
- **⏭️ Skipped:** 1
- **⛔ Blocked:** 1
- **⏱️ Duration:** 00:04:03

| Test Case ID | Test Case Name | Status | Duration |
| --- | --- | --- | --- |
| login_test | login_test | ✅ Passed | 00:01:12 |
| checkout_test | checkout_test | ❌ Failed | 00:02:03 |
| navigation_test | navigation_test | ⏭️ Skipped | 00:00:48 |
| settings_test | settings_test | ⛔ Blocked | — |

# ❌ Fails

## checkout_test
The pay button never appeared after entering the voucher code.

# ⛔ Blocked

## settings_test
Not run: the operator stopped the run before this test.

# ⏭️ Skipped

## navigation_test
No navigation app on this head unit.
```

The summary comes from the recorded results, not from the execution
reports, so it is complete even for tests without a report. A test whose
result cannot be read is `BROKEN`, with the note "No result recorded". Tests
that a [test plan](/docs/writing-tests/plans) selected but the run never
finished are listed under **⛔ Blocked** with their
[reason](#tests-that-never-finished), so nothing goes missing silently. The
summary report pane exports the run as PDF, JSON, or JUnit XML:
[Export](/docs/results/export).

<Callout title="Counting rules">
Every status has its own count. `WARNING` counts as passed, and also in its
own warning count. The pass rate is passed ÷ (passed + failed). The
conclusive share is the conclusive tests out of every counted test.
`DISCARDED` and `DEPRECATED` tests show in the table but count as nothing.
A setup that did not pass counts as one broken test. The Runs page, the
Dashboard, the CLI, and the Management Report count with these rules, so
their figures always agree. Details:
[Test statuses](/docs/results/test-statuses#pass-rate-and-conclusive-share).
</Callout>

In CI, upload the whole workspace folder as a build artifact so the reports
and screenshots stay attached to the run even when tests fail:

```yaml title=".github/workflows/ui-tests.yml"
- uses: actions/upload-artifact@v4
  if: always()
  with:
    name: askui-run
    path: agent_workspace/
```
