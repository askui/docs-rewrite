### Debugging a failing run

The fastest way to debug a failing run:

1. Open the failing test's [execution report](/docs/results/run-report#execution-report) (the `.md` file in
   the run's folder, or inline in AskUI Desktop).
2. Find the first step with status `FAILED` or `BROKEN`, that is where to
   focus.
3. Check the screenshot for that step. `FAILED` means the expected outcome
   didn't match; `BROKEN` means an infrastructure problem (connection lost,
   session expired) stopped the run.
4. For AgentOS issues, check the [logs](/docs/troubleshooting#logs) for more
   detail.

If you cannot resolve the issue yourself, see [Get help](/docs/support/get-help)
for how to generate a diagnostic report and contact support.

### Run completes with 0 results ("No tests ran")

The run started but found no test files to execute.

1. Check that you're running from the correct **Project root**, the folder that
   contains `tests/`, `plans/`, etc.
2. Check that your test files are inside `tests/` and have a supported extension
   (`.md`, `.txt`, `.pdf`, `.csv`, `.json`).
3. If you used `--plan`, check that the plan file exists in `plans/` and
   references valid test paths.

### Run stops with "has the same id as"

Two device profiles in `devices.json` share one id. The app never writes such a
list, so it comes from a hand edit or a merge. Every lookup by id would take the
first of the two: a run on the second device would get the first device's
prompt. So AskUI Desktop refuses to connect either device, and no test of the
run starts.

The run names both profiles, for example:

```text
'Porsche HIL Bench' has the same id 'hil-bench' as 'Audi HIL Bench'. Press Fix it on the Devices page, then start the run again.
```

1. Open **Devices**. The page shows **Duplicated ID. Should we fix this for you?**
   with one line per profile.
2. Click **Fix it**. The first profile keeps its id, so test plans that name it
   still find the same device. Each later one gets its own id (`hil-bench-2`, …),
   and a message names the new ids.
3. Start the run again.

The AskUI CLI stops before the run with exit code 3. Its message names the file
instead of the button, for example
`'Porsche HIL Bench' has the same id 'hil-bench' as 'Audi HIL Bench'. Give each profile its own id in <project>/devices.json.`
Change the `id` of the later profile there, or press **Fix it** in AskUI Desktop.
