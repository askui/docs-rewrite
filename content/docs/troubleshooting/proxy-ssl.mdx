description: Configure the network proxy inside the app and fix TLS errors caused by traffic-inspecting corporate proxies.

### Configure the proxy

The proxy is configured **in the app**, no environment variables:

1. Open **Settings → Network proxy**. (During license setup, the same form
   is in the wizard under **Behind a proxy? Configure network access**.)
2. Choose the **Proxy** mode:
   - **Use system proxy (recommended)**: the Windows proxy/PAC
     configuration applies.
   - **Manual proxy address**: enter the fields:
     - **Proxy address**: e.g. `http://proxy.corp.example:8080`
     - **Bypass for**: hosts reached directly, separated by semicolons
       (e.g. `*.corp.example; 10.0.0.*`). Localhost is always bypassed.
   - **No proxy (direct connection)**.
3. Choose **Proxy authentication**:
   - **Automatic (recommended)**: if the proxy asks for sign-in
     (HTTP 407), your current OS account answers automatically
     (NTLM / Kerberos). No password is stored, and nothing is sent unless
     the proxy actually asks.
   - **Username and password**: stored encrypted on this machine; it
     never leaves it.
   - **Never authenticate**.

### TLS errors behind inspecting proxies (Zscaler and similar)

Some corporate proxies inspect HTTPS traffic and re-sign it with their own
root certificate. The app then reports:

```
The secure (TLS) connection could not be established.
```

1. Check your internet connection first, an interrupted connection fails
   with this same error.
2. If you are online and on a corporate network, ask your IT department to
   **install the corporate root certificate into the Windows certificate
   store**, or to exclude the app's endpoints from inspection.

There is no switch to disable TLS verification, the certificate has to be
trusted by the OS.
