---
title: Install the CLI
description: Set up the AskUI CLI to run Projects headless, from a terminal or in CI.
---

The AskUI CLI (`askui`) runs the same Projects you author in AskUI Desktop,
without the UI. One command, `askui run`, executes your tests on the
Project's device, a desktop, a browser, an Android device, or an iOS
simulator, and writes the reports of the run. Use it locally for scripted
runs, or in CI.

<Steps>

<Step>
**Install the CLI**

The CLI ships with [AskUI Desktop](/docs/get-started/install-desktop).

<Tabs items={['Windows', 'macOS', 'CI runner']}>
  <Tab value="Windows">
    The AskUI Desktop installer puts `askui` on your `PATH`, and the
    uninstaller removes it again. Open a new terminal after the install.

    **Settings → This machine → Command line** shows whether that worked. If
    a locked-down PowerShell stopped the installer from changing `PATH`, the
    card says so and shows where `askui.exe` is. Reinstall, or add its folder
    to your user `PATH` by hand.
  </Tab>
  <Tab value="macOS">
    Dragging the app into Applications runs no installer, so you add the
    command once: open **Settings → This machine → Command line** and click
    **Add to PATH**. AskUI Desktop links `~/.local/bin/askui` to the CLI inside
    the app. It adds `~/.local/bin` to your `PATH` in `~/.zprofile` and
    `~/.zshrc` (for bash, `~/.bash_profile` and `~/.bashrc`), where it is not
    there yet. Both matter: the terminal of an editor such as VS Code reads only
    `~/.zshrc`. Open a new terminal afterwards.

    If you move the app, the card offers **Repair**; **Remove** takes the
    link away again. Start the app from Applications, not from the disk
    image: a link to the disk image breaks when you eject it, so the card asks
    you to move the app first.
  </Tab>
  <Tab value="CI runner">
    A build server gets AskUI Desktop too, since the CLI ships inside it.
    Install it as on Windows or macOS above. See
    [AskUI in CI](/docs/guides/askui-in-ci#1-get-the-cli-onto-the-runner) for
    what a runner service needs on top.

    Linux runners are not supported yet: AskUI Desktop has no Linux version,
    and a standalone CLI download is planned.
  </Tab>
</Tabs>
</Step>

<Step>
**Verify the install**

```bash
askui --version
askui run --help
```

`askui run --help` lists every option, the environment variables, and the
exit codes.
</Step>

<Step>
**Set up the device you want to drive**

The CLI runs on the Project's [device profiles](/docs/devices) in
`devices.json`, the same ones the app uses (see
[Choosing the device](/docs/running-tests/cli#choosing-the-device)). The
CLI starts an emulator or a simulator that a profile provisions, as the
app does.

<Tabs items={['Desktop (AgentOS)', 'Browser', 'Android', 'iOS']}>
  <Tab value="Desktop (AgentOS)">
    Desktop runs need [AgentOS](/docs/agentos) on the machine under test. For
    a profile on `localhost`, the CLI **starts a local AgentOS** for the run
    when none is running. For a remote machine, install AgentOS there and set
    the profile's host and port to it; the CLI attaches to a remote AgentOS
    instead of starting one.
  </Tab>
  <Tab value="Browser">
    The CLI downloads the browser it drives (Chromium via Playwright) the
    first time it connects, so the machine needs internet access for that
    first run.
  </Tab>
  <Tab value="Android">
    `adb` must be on your `PATH`. A physical device must be connected and
    visible to `adb devices`. An emulator profile starts the emulator with
    the Android SDK that AskUI Desktop set up. See the
    [ADB setup guide](/docs/agentos/deployment/local#android-setting-up-adb).
  </Tab>
  <Tab value="iOS">
    A booted simulator or a connected device with the profile's udid, and
    `idb_companion` for a simulator.
  </Tab>
</Tabs>
</Step>

<Step>
**Authenticate**

If AskUI Desktop runs with a **local license** on the machine, skip this step.
The CLI then uses the license and the model you set up in the app, as the app
does, and `askui status` shows that model.

Otherwise, the CLI authenticates with an access token of your workspace. Create
one in the [AskUI Hub](https://hub.askui.com) under your workspace's **Access
tokens** (see [Workspaces & access tokens](/docs/account-billing/workspaces)),
and set two environment variables:

```bash
export ASKUI_WORKSPACE_ID="<your workspace id>"
export ASKUI_TOKEN="<your access token>"
```

Instead of exporting, you can also put both lines in a `.env` file in your
Project root. The CLI loads it on every run, and variables already set in the
environment win. A new Project's `.gitignore` already keeps `.env` out of git.
You choose the token's lifetime in the Hub, so the same setup works for a
scheduled job and a CI runner.

`askui login` and `askui logout` are not available yet: they print how to set
the two variables and stop with exit code 3. To sign the CLI out, unset the
variables, and delete the token in the Hub when you no longer need it.

`askui status` shows what a run on this machine uses: whether AskUI Desktop's
settings count, the kind of credential, the workspace, the token by its last
three characters, the entitlement, and the model.
</Step>

<Step>
**Run a Project**

```bash
cd my-project
askui run
```

See [Running from the CLI](/docs/running-tests/cli) for the full
command reference, test plans, devices, model selection, reports, and exit
codes.
</Step>

</Steps>
