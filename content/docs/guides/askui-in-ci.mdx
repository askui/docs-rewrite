The project your team authors in AskUI Desktop runs unchanged on a build
server, same testware, headless execution, and the pipeline fails exactly
when a test fails.

## 1: Get the CLI onto the runner

The CLI ships inside AskUI Desktop, so the runner gets AskUI Desktop. On a
self-hosted runner, install it once like on any machine
([Install the CLI](/docs/running-tests/install-cli)). To install it in the
pipeline itself, take the installer of the version you want from the
release's **Downloads** table. The versioned link pins that version.

On a **Windows** runner, the installer runs silently with `/S` and puts
`askui` on the user's `PATH`. A runner that is already running does not see
that change, so add the folder for the next steps yourself, here for GitHub
Actions:

```powershell
Invoke-WebRequest "<installer URL>" -OutFile askui-setup.exe
Start-Process .\askui-setup.exe -ArgumentList '/S' -Wait
"$env:LOCALAPPDATA\Programs\AskUI Desktop\bin" | Out-File -Append $env:GITHUB_PATH
```

On a **macOS** runner, copy the app out of the disk image and link the CLI
into a folder on `PATH`:

```bash
curl -fsSL "<disk image URL>" -o askui.dmg
hdiutil attach askui.dmg -nobrowse -mountpoint /Volumes/AskUI
cp -R "/Volumes/AskUI/AskUI Desktop.app" /Applications/
hdiutil detach /Volumes/AskUI
mkdir -p ~/.local/bin
ln -sf "/Applications/AskUI Desktop.app/Contents/MacOS/askui" ~/.local/bin/askui
echo "$HOME/.local/bin" >> "$GITHUB_PATH"
```

Then check the version in the next step: `askui --version`.

<Callout type="warn">
Linux runners are not supported yet: AskUI Desktop has no Linux version.
A standalone CLI download for CI runners is planned.
</Callout>

Provide credentials as environment variables from the CI secret store:
`ASKUI_WORKSPACE_ID` and `ASKUI_TOKEN` (create the token in the
[Hub](/docs/account-billing/workspaces)). The same goes for every value the
project references: a `${VAR}` in a device profile, and every
[secret](/docs/running-tests/cli#secrets-in-a-headless-run), resolve from
the environment variable of that name.

## 2: Give it a device

The CLI runs on the project's [device profiles](/docs/devices), picked with
`--device` by id or name, or the plan's device. Leave the runner-specific
parts to the runner: write `${AGENTOS_HOST}` or `${ANDROID_SERIAL}` into the
profile's host or serial, and set the variable in the pipeline (see
[Environment variables in a profile](/docs/running-tests/cli#environment-variables-in-a-profile)).

A [browser](/docs/devices/web-browser) runs on the bare runner; use a
profile with **Headless** on when the runner has no display.
Desktop targets need a test machine with
[AgentOS](/docs/agentos/deployment/ci) the runner can reach. The CLI
connects to a device, it does not start an emulator, a simulator, or a VM,
so start it in an earlier pipeline step.

### Runner requirements

AskUI Desktop carries the CLI and the browser driver. Each device kind needs
more on the runner:

| Device | The runner needs |
| --- | --- |
| Browser (`web`) | Internet access on the first web run, when the CLI downloads Chromium. |
| Desktop (`agent-os`) | The AskUI [AgentOS](/docs/agentos) controller, running and listening at the profile's host and port. |
| Android | `adb` on `PATH`, and the device or emulator already running. The profile's serial picks the device. |
| iOS | A booted simulator or a connected device with the profile's udid, and `idb_companion` for a simulator. |

Every device needs outbound HTTPS to the model: the AskUI hub, or the
endpoint of `--model-endpoint` (see
[Network requirements](/docs/reference/network-requirements)). A project with
[custom tools](/docs/extending/custom-tools) also needs NuGet access for
their `#:package` lines: nuget.org, or the feeds of the runner's
`NuGet.config`.

## 3: Run a plan

```bash
askui run --plan smoke --output ./run-artifacts --reporter html,md,junit
```

In a pipeline the CLI never prompts, and prints one plain line per event.
Gate the pipeline on the exit code:

| Code | Meaning |
| --- | --- |
| `0` | All tests passed. |
| `1` | A test failed, broke, or was never reached: the product team acts. |
| `2` | The command line is wrong. |
| `3` | The runner or the project is wrong: credentials, device, MCP server, an unset `${VAR}`. Nothing was sent to the model. |
| `4` | No test ran, for example an empty plan. |
| `130` | Canceled. |

Archive the output folder as the build artifact, reports and screenshots
included; the [CLI reference](/docs/running-tests/cli) has every option.

## 4: Publish the test report

With `--reporter` including `junit`, the run writes `<output>/junit.xml`, and
your CI system shows pass and fail per test. `FAILED` is a failure, `BROKEN`
and a test the run never reached are errors, and a `WARNING` passes with its
notes in the test output ([JUnit mapping](/docs/running-tests/cli#junit-mapping)).

<Tabs items={['GitHub Actions', 'GitLab CI']}>
  <Tab value="GitHub Actions">
    ```yaml title=".github/workflows/ui-tests.yml"
    jobs:
      ui-tests:
        runs-on: [self-hosted, askui]
        permissions:
          contents: read
          checks: write
        env:
          ASKUI_WORKSPACE_ID: ${{ vars.ASKUI_WORKSPACE_ID }}
          ASKUI_TOKEN: ${{ secrets.ASKUI_TOKEN }}
        steps:
          - uses: actions/checkout@v4
          - run: askui run --plan smoke --output ./run-artifacts --reporter html,md,junit
          - uses: actions/upload-artifact@v4
            if: always()
            with:
              name: askui-run
              path: ./run-artifacts
          - uses: dorny/test-reporter@v1
            if: always()
            with:
              name: AskUI tests
              path: run-artifacts/junit.xml
              reporter: java-junit
    ```
  </Tab>
  <Tab value="GitLab CI">
    ```yaml title=".gitlab-ci.yml"
    askui-tests:
      stage: test
      tags:
        - askui
      script:
        - askui run --plan smoke --output run-artifacts --reporter html,md,junit
      artifacts:
        when: always
        paths:
          - run-artifacts/
        reports:
          junit: run-artifacts/junit.xml
        expire_in: 7 days
    ```
  </Tab>
</Tabs>
