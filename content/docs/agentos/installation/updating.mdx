AgentOS installed with the Windows service installer ships with its own updater.
It runs as a separate Windows service, **AskUI AgentOS Updater**, and installs
new versions in the background.

<Callout title="Note">
This page applies to installs made with the [OS Service](/docs/agentos/installation/service)
or [Silent](/docs/agentos/installation/silent) installer. A `pip` install is
updated with `pip install --upgrade askui-agent-os`.
</Callout>

## Automatic updates

- **Check interval** — every 2 days. The updater compares the installed version
  against the update feed.
- **No prompt** — a newer version is downloaded and installed silently. Users
  are not asked to accept or defer.
- **No elevation prompt** — the check and the install are performed by the
  **AskUI AgentOS Updater** service, which runs as `LocalSystem`. A signed-in
  standard user sees no UAC dialog and needs no administrator rights.
- **Configuration is preserved** — files written by the previous version are
  kept, not overwritten. This includes your activated license key.

Machines that must stay on a fixed version can
[turn automatic updates off](#turn-off-automatic-updates).

## Manual update

Three ways to update on demand. All of them keep your configuration and your
license key.

**Run the updater from the notification area.**

1. Open the notification area at the right end of the Windows taskbar.
2. Find the **AskUI AgentOS** icon and click it.

**Run the updater from the command line.**

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /checknow
```

<Callout type="warn">
Double-clicking **AskUI AgentOS Updater.exe** appears to do nothing. It runs a
silent check and closes without a window. To change settings, use the
**AskUI AgentOS Update Settings** shortcut in the same folder, see
[Configure the updater](#configure-the-updater). To update, pass a command such
as `/checknow`, see [Updater commands](#updater-commands).
</Callout>

Both routes rely on the **AskUI AgentOS Updater** service to install without an
elevation prompt. If you have [turned automatic updates off](#turn-off-automatic-updates)
by disabling that service, a standard user can no longer update this way.

**Install the new version yourself.** Use this when the machine cannot reach the
update feed, or when you roll a specific version out across a fleet.

1. Download the current installer, [AMD64](https://files.askui.com/releases/Installer/Latest/AskUI-Agent-OS-Latest-Service-Installer-Win-AMD64.exe)
   or [ARM64](https://files.askui.com/releases/Installer/Latest/AskUI-Agent-OS-Latest-Service-Installer-Win-ARM64.exe).
2. Run it on the existing installation. It upgrades in place, no uninstall
   first.

This route needs administrator rights, same as the original install. For
unattended rollout, see [Silent (exe)](/docs/agentos/installation/silent).

## Check the installed version

1. Open **Settings → Apps → Installed apps**.
2. Search for **AskUI AgentOS**.
3. Read the version next to the entry.

<Callout type="warn">
Installed is not the same as running. To confirm the AgentOS service is up, see
[AgentOS service issues](/docs/troubleshooting/agentos-service#restart-the-agentos-service).
</Callout>

## Updater commands

The updater is installed at:

```text
C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe
```

The path contains spaces, so always quote it. In **Command Prompt** and in the
**Win+R** run box, quote the path on its own:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /configure
```

In **PowerShell**, add the call operator `&` in front, otherwise the quoted path
is treated as text and nothing runs:

```powershell
& "C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /configure
```

### Commands

| Command | What it does |
| --- | --- |
| `/configure` | Opens the configuration window |
| `/checknow` | Checks now and shows the result, whether or not an update was found |
| `/justcheck` | Checks and returns a result code, without a window and without installing |
| `/silent` | Checks quietly, and only opens a window if an update is found |
| `/silentall` | Checks quietly and installs every available update |
| `/silentcritical` | Checks quietly and installs only critical updates |

`/checknow` and `/justcheck` check straight away. `/silent`, `/silentall` and
`/silentcritical` honour the check interval, so they may do nothing if the last
check was recent.

### Options

Add these to a command to change how that one run behaves. They are not saved.

| Option | What it does |
| --- | --- |
| `-url <address>` | Uses a different update feed for this run |
| `-justdownload` | Downloads updates without installing them |
| `-nogui` | Runs without a window |
| `-reducedgui` | Runs with a minimal window |

Example — check against a test feed without installing anything:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /justcheck -url "https://updates.example.com/agentos/updates.txt"
```

### Saved settings

`/set` changes a setting and keeps it, so these are the scriptable equivalent of
the [configuration window](#configure-the-updater). The value follows the setting
name, with no dash. No administrator rights are needed, and the settings apply to
the account that ran the command.

| Command | Accepted values |
| --- | --- |
| `/set autoupdatepolicy <policy>` | `Disable`, `Prompt`, `AutoCritical`, `AutoAll` |
| `/set downloadsfolder <folder>` | Any writable folder |
| `/set proxy <host:port>` | An address or a name, with the port |
| `/set retryattempts <count>` | `0` to `6` |
| `/set loglevel <levels>` | `Error`, `Trace`, `Debug`, `Off`. Combine with `\|` |
| `/set rememberpassword <user> <password>` | Credentials for a protected feed |

<Callout type="warn">
Quote any value containing `|`, because both Command Prompt and PowerShell read
it as a pipe: `/set loglevel "Debug|Trace"`.
</Callout>

The update policies are:

| Policy | Behaviour |
| --- | --- |
| `Disable` | Never check automatically |
| `Prompt` | Check, then ask before installing |
| `AutoCritical` | Install critical updates automatically, ask about the rest |
| `AutoAll` | Install every update automatically |

Until you set a policy, the updater follows the default chosen by the installer,
which installs updates automatically.

Example — stop this machine installing updates on its own:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /set autoupdatepolicy Disable
```

<Callout title="Note">
There is no `/set` option for the update feed or the check interval. Change the
feed in the [configuration file](#change-the-update-feed), and the interval in
the [configuration window](#configure-the-updater).
</Callout>

## Configure the updater

Open the install folder and double-click **AskUI AgentOS Update Settings**:

```text
C:\Program Files\askui GmbH\AskUI AgentOS\
```

Or open the same window from a command line:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /configure
```

No administrator rights needed. The window sets:

- **Automatic update policy** — whether the updater checks on its own
- **Check interval** — how many days between checks
- **Download folder** — where installers are staged before they run

These settings apply to the account that changed them, and they are kept when
AgentOS updates.

The policy and the download folder can also be set without opening the window,
see [Saved settings](#saved-settings). That is the route to use when rolling a
setting out across many machines.

<Callout type="warn">
Do not set the check interval to `0` to switch updates off. A zero interval does
not mean "never" — it makes the updater check every time it runs. Use the
automatic update policy instead.
</Callout>

## Change the update feed

Machines that must not reach `files.askui.com` can pull updates from your own
artifact registry, such as Artifactory.

**Try it first without changing anything.** `-url` overrides the feed for a
single run, so you can confirm your mirror answers correctly before committing
to it:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /justcheck -url "https://updates.example.com/agentos/updates.txt"
```

**Then make it permanent.** The feed is a machine-wide setting in:

```text
C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.ini
```

Change the `URL` value:

```ini
[General]
URL=https://updates.example.com/agentos/updates.txt
```

The file is under `C:\Program Files`, so editing it needs administrator rights.

<Callout type="warn">
Installing an update rewrites this file, including `URL`. Deploy your edited
copy from configuration management and re-apply it after each version change,
the same way you deploy the [silent installer](/docs/agentos/installation/silent).
Otherwise the machine silently returns to the AskUI feed.
</Callout>

Mirror both the update feed and the installers it references into your registry,
or the updater will find a new version and fail to download it.

## Turn off automatic updates

**For one user**, set the update policy to `Disable`:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /set autoupdatepolicy Disable
```

To allow updates again, choose the policy you want, for example `AutoAll` to
restore the installed default or `Prompt` to be asked first:

```cmd
"C:\Program Files\askui GmbH\AskUI AgentOS\AskUI AgentOS Updater.exe" /set autoupdatepolicy AutoAll
```

The same setting is in the [configuration window](#configure-the-updater) if you
prefer to change it there.

**For the whole machine**, disable the updater service, which owns the scheduled
check:

```cmd
sc.exe stop "AskUI AgentOS Updater"
sc.exe config "AskUI AgentOS Updater" start= disabled
```

The space after `start=` is required by `sc.exe`. To switch automatic updates
back on, restore the installed default:

```cmd
sc.exe config "AskUI AgentOS Updater" start= demand
```

Check the current state at any time:

```cmd
sc.exe qc "AskUI AgentOS Updater"
```

<Callout type="warn">
Disabling the service also removes the non-elevated manual update path. With the
service off, updating the machine requires an administrator to run the installer.

Repairing, modifying or upgrading AgentOS re-registers the service and can
re-enable it. Confirm with `sc.exe qc` after any of those.
</Callout>

A machine with automatic updates off never picks up fixes on its own. Plan a
managed rollout for it.

## Verify after an update

- **Version** — increased, see [Check the installed version](#check-the-installed-version).
- **Service** — **AskUI.AgentOS.Service** is running again, see
  [AgentOS service issues](/docs/troubleshooting/agentos-service#restart-the-agentos-service).
- **Updater** — if you disabled automatic updates, **AskUI AgentOS Updater** is
  still disabled.
- **Update feed** — if you use your own registry, `URL` in
  `AskUI AgentOS Updater.ini` still points at it.
- **Firewall** — your inbound rule for the AgentOS port still exists, if you
  added one.
- **License** — your license is still active. An update keeps the configuration
  written by the previous version instead of overwriting it, so the key survives.
