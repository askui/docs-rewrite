Find your first bug in 10 minutes. This guide takes you from a blank machine to
your first test run, no selectors, no code, just plain language. Four steps:
download AskUI Desktop, sign in, walk the onboarding wizard, and run the
template's example test on your own machine.

<Callout title="What you need">
A Windows or macOS machine. No prior automation experience required.
</Callout>

---

## Step 1: Download AskUI Desktop (2 min)

Grab the installer for your platform and run it. It's self-contained, no
extra runtimes needed.

<Cards>
  <Card
    title="Windows (x64)"
    href="https://files.askui.com/releases/AskUIDesktop/latest/AskUI-Desktop-latest-Installer-Win-AMD64.exe"
    description="Signed, self-contained."
  />
  <Card
    title="macOS (Apple Silicon)"
    href="https://files.askui.com/releases/AskUIDesktop/latest/AskUI-Desktop-latest-Installer-Mac-ARM64.dmg"
    description="Notarized, Apple Silicon."
  />
</Cards>

<Tabs items={['Windows', 'macOS']}>
  <Tab value="Windows">
    Run the `.exe` and follow the guided setup.
  </Tab>
  <Tab value="macOS">
    Open the `.dmg` and drag AskUI Desktop into Applications. You'll grant
    screen and input permissions during the onboarding wizard in Step 3.
  </Tab>
</Tabs>

<Callout title="Always the latest">
These links always give you the newest release. The installers are also on
the [AskUI download page](https://www.askui.com/start) and your
[AskUI Hub](https://hub.askui.com) account page.
</Callout>

## Step 2: Sign up or log in (2 min)

Launch AskUI Desktop and sign in with your AskUI account.

<Steps>
<Step>
**New to AskUI?** Click **Create account** to create an account with your work email,
accept the terms, and verify your email from the link we send. Accounts and
billing live in the [AskUI Hub](https://hub.askui.com).
</Step>
<Step>
**Already have an account?** Click **Sign in** and authenticate in your browser.
The same login works across Desktop and the Hub. The CLI authenticates with
an [access token](/docs/account-billing/workspaces) instead.
</Step>
</Steps>

<Callout title="Note">
Authentication uses Auth0 (OIDC) and opens in your system browser.
</Callout>

---

## Step 3: Walk the onboarding wizard (3 min)

On first launch, AskUI Desktop opens a short setup wizard.

<Steps>
<Step>
**Welcome.** Click **Get set up**.
</Step>
<Step>
**Grant system permissions** *(macOS only).* Allow **Screen Recording** and
**Accessibility** so the agent can see the screen and control input. The status
flips green automatically once granted.
</Step>
<Step>
**Where do you want to test?** Tick **Web**, **Desktop** and/or **Android**.
Whatever this computer already has is ticked for you. Ticking a kind starts
setting up what it needs right away, in the background, with its progress on the
card: the Chromium browser for Web (about 170 MB), AgentOS for Desktop, and, once
you accept Google's licenses, the Android SDK and an emulator (about 1–1.5 GB). You
can continue while it downloads.
</Step>
<Step>
**You're ready to test.** Watch the short quick start video, or open the tutorial
series. Then click **Start with the demo project**: AskUI creates it in
`Documents/AskUI demo project` (or **Choose another folder**) and opens it.
**Skip the demo** opens the app without a project.
</Step>
</Steps>

The demo project tests the AskUI website. Its first device is the web browser, or
this computer when you ticked Desktop, so its test runs without any setup.

## Step 4: Follow Getting started (5 min)

The dashboard walks you to your first passing test:

- A short **tour** shows where things are: Getting started, Tests, Devices and
  Runs (**Next**, or **Skip tour**).
- **Getting started** shows four steps and the next one to do: **Open the demo
  test**, **Run the test**, **Get it to pass**, **Look at the results**. Its
  button takes you there. On every other page the same steps sit in a small card
  at the bottom right, which you can fold away.
- On the test, **Run** is highlighted. While the test runs, Getting started says
  so; when it ends, **View results** opens its report.
- On the Runs page a short tour explains the run's reports, from the top of the
  list: the conversation log, the summary report, the Developer Report, the
  execution report and Export.
- **Setting up your devices** on the dashboard shows the downloads still running,
  with the time left, and **Retry** or **Resume** when one stopped. The same
  downloads show under **Settings → This machine**.

To walk the wizard and Getting started again, open **Settings → This machine →
Setup assistant**.

<Callout title="Make it yours">
Once the demo test passes, open `tests/ui.md` on the Tests page and describe your own
app, its main screens, how to tell you're signed in, and any quirks. It's the
single most important file for reliable runs. See
[Prompting best practices](/docs/best-practices/prompting-best-practices).
</Callout>

## Optional: Install AgentOS to automate a computer

Runs are powered by **AgentOS**, the runtime that actually controls a computer,
its screen, keyboard, and mouse. Desktop does **not** bundle it. To run tests on
a computer, such as your local machine, AgentOS must be installed on whichever
computer you want to automate. This can be your own machine, a remote host, a
headless CI runner, or a device in a fleet.

<Callout title="AgentOS on this computer">
For the computer AskUI Desktop runs on, you don't need to install it by hand: tick
**Desktop** in the onboarding wizard, or open **Settings → This machine → AgentOS**
and click **Download AgentOS**. The app downloads the release for your computer,
checks that it is signed by askui GmbH and points itself at it. Install it by hand
for any other computer you want to automate.
</Callout>

You can install AgentOS in one of two ways:

<Cards>
  <Card title="Standalone" href="/docs/agentos/installation/standalone"
    description="Run AgentOS as a regular process in your user session, the fastest option for a dev machine." />
  <Card title="OS Service (Windows)" href="/docs/agentos/installation/service"
    description="Install as a system service for CI/CD and headless VMs that boot to the login screen." />
</Cards>

For a **standalone** installation, download the ZIP for your platform, unpack it
and point the app at the controller inside it:

<Steps>
<Step>
Download AgentOS for
[Windows AMD64](https://files.askui.com/releases/UIController/26.7.1/RemoteDeviceController-26.7.1-Windows-x64.zip),
[Windows ARM64](https://files.askui.com/releases/UIController/26.7.1/RemoteDeviceController-26.7.1-Windows-ARM64.zip)
or [macOS ARM64](https://files.askui.com/releases/UIController/26.7.1/RemoteDeviceController-26.7.1-MacOS-ARM64.zip)
(Apple silicon). For a Linux machine (X11 only, no Wayland) there are
[Linux AMD64](https://files.askui.com/releases/UIController/26.7.1/RemoteDeviceController-26.7.1-Linux-x64.zip)
and [Linux ARM64](https://files.askui.com/releases/UIController/26.7.1/RemoteDeviceController-26.7.1-Linux-ARM64.zip)
builds, see [Standalone installation](/docs/agentos/installation/standalone).
</Step>
<Step>
Unpack it into a folder of its own, for example `C:\Users\<you>\AskUI\AgentOS` on Windows
or `/Users/<you>/AskUI/AgentOS` on macOS. The archive has no top-level folder,
so create the folder first.
</Step>
<Step>
Open **Settings** in AskUI Desktop, go to **This machine**, and paste the full
path to the controller under **Agent OS → Controller path**, for example:

```
C:\Users\<you>\AskUI\AgentOS\AskuiRemoteDeviceController.exe
```

```
/Users/<you>/AskUI/AgentOS/AskuiRemoteDeviceController
```
</Step>
</Steps>

See [Standalone installation](/docs/agentos/installation/standalone) for how to
copy the path on each platform.
