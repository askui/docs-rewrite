The **Reporting** tab decides how your tests are reported. Open
**Extending → Reporting**. It has three settings:

- **Create report**: which tests get an execution report.
- **Reporting model**: which model writes the reports.
- **Report format**: the template every report follows (`utils/format.md`).

The first two are saved in your Project's `askui.json`, the format in
`utils/format.md`. Both files travel with the Project, so a colleague's clone
uses the same settings.

## How a test is reported

The agent ends each test by recording a **result**: a status and a short
reason. It picks the status by AskUI's
[status definitions](#status-definitions). That recorded result decides
whether the test passed. A test that records nothing is `BROKEN`.

The **execution report** is written after the test, by a separate agent. It
reads the test's conversation and screenshots and writes the report in the
shape of `utils/format.md`. The next test starts at once, and the report is
written in the background. A report never changes the result of a test.
What a report contains: [Execution report](/docs/results/run-report#execution-report).

## Create report

| Option | What it does |
| --- | --- |
| **Always** | Every finished test gets a report. This is the default, also for projects that existed before this setting. |
| **Only for failed or broken tests** | Passed tests get no report. This is the cheapest way to keep the reports you read. |
| **Never** | No report is written during runs. |

A [test plan](/docs/writing-tests/plans#build-a-plan) can override this
setting for its own runs. The order is: the plan's setting, else the
project's, else **Always**.

Every report costs model tokens. With **Only for failed or broken tests** or
**Never**, you can still write a report later. Right-click the test on the
**Runs** page and pick **Generate execution report**:
[Write a report later](/docs/results#write-a-report-later).

## Reporting model

The model that writes the reports, under **Reporting model**. A report reads
one test, so the model of your test runs is usually enough. Pick a stronger one
for more careful reports. The model must read screenshots.

- **Use the global model**: on by default. The model under **Settings → AI
  Settings → Global Model** writes the reports, shown in brackets beside the checkbox.
- Clear it to pick another model in the same form as on Settings. Signed in to
  AskUI, pick a hosted model, or **Best** or **Fastest**. With a license, set up
  a provider of your own ([Your own model](/docs/extending/model-providers)).

The choice belongs to the Project.

## Status definitions

Every project uses AskUI's status definitions. They define when a test is
`PASSED`, `FAILED`, `WARNING`, `BROKEN`, or `SKIPPED`. The testing agent
gets them in its instructions and picks the status it records by them.
Setups and teardowns use them too.

The first run of a project writes them to `utils/status.md`, and the agent
reads them from there. The app does not offer the file for editing:

```markdown title="utils/status.md"
- **PASSED** — every step ran and the expected outcome was observed.
- **FAILED** — the system did not behave as the test expects: an expected outcome was not observed, or a step is not applicable to what the screen shows.
- **WARNING** — the expected outcome was observed, but something noteworthy went wrong on the way (e.g. a slow response, a minor visual deviation).
- **BROKEN** — the test could not be executed because of an error that is not the system under test (crash, infrastructure or tool failure, exception).
- **SKIPPED** — the test was intentionally not executed (e.g. its precondition was not met).
```

Because every project uses the same definitions, a `PASSED` means the same
thing in every project. The summary report, the Dashboard, and the
Management Report count these five statuses.

## Report format

The **Report format** section is collapsed below the other settings. Click
it to open the editor for `utils/format.md`. Changes save automatically, and
the file applies to every report of the project.

If the project has no `utils/format.md` yet, click **Create utils/format.md**.
It starts from the default format.

The format instructs the report writer, not the testing agent. Keep these
parts:

- **The step statuses** (`PASSED`, `FAILED`, `SKIPPED`, `WARNING`, `BROKEN`):
  the default format asks the writer to judge each step like the
  [status definitions](#status-definitions).
- **The overall status**: the report states the status that the test
  recorded. The format cannot change the result of a test.
- **The screenshot syntax**: the writer gets the test's screenshots with
  file names such as `screenshot_3.png`. It embeds each one as
  `![Step 1](screenshot_3.png)`, so the image shows in the report.

The writer embeds exactly one screenshot per step, the one that shows the
step's outcome, and a second only as a rare exception, for example a
before-and-after comparison. This holds whatever the format says, and the
default format says the same. The sections, the wording, and the level of
evidence are yours to tailor:
[the report contract](/docs/best-practices/agent-behavior#report-format-the-report-contract).

## The settings in `askui.json`

The `reporting` section under `config` in the Project's `askui.json` holds the
first two settings:

```json title="askui.json (excerpt)"
{
  "config": {
    "reporting": {
      "createReport": "failures",
      "model": { "modelId": "claude-haiku-5-5" }
    }
  }
}
```

**`createReport`** sets when an execution report is written. A
[test plan](/docs/writing-tests/plans#build-a-plan) can override it.

- `always`: after every test.
- `failures`: only for tests that ended `FAILED` or `BROKEN`.
- `never`: none during the run. You can still write them later from the
  **Runs** page.

**`model`** sets which model writes the reports: a `provider`, by its name,
and a `modelId`. What it leaves empty comes from the global model, so an empty
`model` writes the reports with the global model. A provider's endpoint and
API key never sit in the Project: they stay on each tester's machine.

A Project without these settings uses `always` and the global model. A
Project's older `utils/reporting.json` moves into `askui.json` the first time
AskUI Desktop opens it or the CLI reads it. To try another value without
changing the Project, or to set it from the terminal, see
[Configure the CLI](/docs/running-tests/cli-configuration#reporting-and-in-flight-guidance).
