The **Reporting** tab decides how your tests are reported. Open
**Extending → Reporting**. It has four settings:

- **Create report**: which tests get an execution report.
- **Reporting model**: which model writes the reports.
- **Software version under test**: the build your runs test.
- **Report format**: the template every report follows (`utils/format.md`).

The settings are saved in `utils/reporting.json` in your project. They travel
with the project, so a colleague's clone and the [CLI](/docs/running-tests/cli)
use the same settings.

## How a test is reported

The agent ends each test by recording a **result**: a status and a short
reason. That recorded result decides whether the test passed. A test that
records nothing is `BROKEN`.

The **execution report** is written after the test, by a separate agent. It
reads the test's conversation and screenshots and writes the report in the
shape of `utils/format.md`. The next test starts at once, and the report is
written in the background. A report never changes the result of a test.
What a report contains: [Execution report](/docs/results/run-report).

## Create report

| Option | What it does |
| --- | --- |
| **Always** | Every finished test gets a report. This is the default, also for projects that existed before this setting. |
| **Only for failed or broken tests** | Passed tests get no report. This is the cheapest way to keep the reports you read. |
| **Never** | No report is written during runs. |

Every report costs model tokens. With **Only for failed or broken tests** or
**Never**, you can still write a report later. Right-click the test on the
**Runs** page and pick **Generate execution report**:
[Write a report later](/docs/results#write-a-report-later).

## Reporting model

The model that writes the reports.

- **On the AskUI hub**, pick from the list:
  - **Same as your test runs**: the default, and the recommended choice. A
    report covers one test, so the model of your runs is usually enough.
  - **Best available**: for more careful reports.
  - **A named hosted model**: any other model the hub serves.
- **With your own model provider**, the **Same as for my test runs**
  checkbox is on by default. Clear it to set up a separate provider for
  reports. The model must read screenshots.

How to connect your own provider: [Model providers](/docs/extending/model-providers).

## Software version under test

Enter the version of the software you test, for example `4.2.1`. Every run
you start while it is set records this version. The
[Management Report](/docs/results/management-report) shows it, and the
exports carry it.

- Change it when you start to test a new build.
- Leave it empty when you do not know the version.
- A change does not rewrite runs that already started.

To correct the version of a finished run, right-click the run on the
**Runs** page and pick **Set software version…**. Clear the field to remove
the version.

## Report format

The **Report format** section is collapsed below the other settings. Click
it to open the editor for `utils/format.md`. Changes save automatically, and
the file applies to every report of the project.

If the project has no `utils/format.md` yet, click **Create utils/format.md**.
It starts from the default format.

The format instructs the report writer, not the testing agent. Keep these
parts:

- **The status definitions** (`PASSED`, `FAILED`, `SKIPPED`, `WARN`,
  `BROKEN`): the vocabulary for each step.
- **The overall status**: the report states the status that the test
  recorded. The format cannot change the result of a test.
- **The screenshot syntax**: the writer gets the test's screenshots with
  file names such as `screenshot_3.png`. It embeds each one as
  `![Step 1](screenshot_3.png)`, so the image shows in the report.

The sections, the wording, and the level of evidence are yours to tailor:
[the report contract](/docs/best-practices/agent-behavior#report-format-the-report-contract).

## The settings file

`utils/reporting.json` holds the first three settings:

```json title="utils/reporting.json"
{
  "createReport": "failures",
  "modelId": "same-as-runs",
  "byomSameAsRuns": true,
  "softwareVersion": "4.2.1"
}
```

| Field | Values |
| --- | --- |
| `createReport` | `always`, `failures`, or `never` |
| `modelId` | `same-as-runs`, `best`, or the id of a hosted model |
| `byomSameAsRuns` | `true` to use your own provider's run model for reports |
| `softwareVersion` | Free text, or absent |

A project without this file uses **Always** and the model of your runs. A
separate provider for reports is stored in the app on your machine, not in
the project.
