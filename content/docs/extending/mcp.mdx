A capability that already exists as an [MCP](https://modelcontextprotocol.io)
server, a Jira bridge, an internal API gateway, doesn't need rebuilding as
a custom tool. Register it; its tools join the agent's toolbox.

## Add a server

1. Open **Extending → MCP Servers**.
2. Click **Add MCP**. The dialog **Add MCP server** opens.
3. Enter **Name**, **URL** (SSE or HTTP), and optional **Headers**, one per
   line, e.g. `Authorization: Bearer ${MCP_TOKEN}`.
4. Leave **Runs go on without this server when it cannot be connected** checked,
   unless your tests cannot run without the server (see
   [A server the tests need](#a-server-the-tests-need)).
5. Click **Add server**.

This writes `utils/mcp.json` in the project, the whole team and the
[CLI in CI](/docs/running-tests/cli) get the same server list:

```json title="utils/mcp.json"
{
  "servers": [
    {
      "name": "issue-tracker",
      "url": "https://mcp.example.com/sse",
      "transport": "sse",
      "enabled": true,
      "headers": { "Authorization": "Bearer ${TRACKER_TOKEN}" }
    }
  ]
}
```

`${VAR}` values resolve at run start, from the project's [secrets](/docs/extending/secrets) first and the environment second, the token never
lands in the file.

Servers connect when a run starts, before the first test. Each server is one
line of the run's **Surface setup** block: it shows that the server is loading,
then that it loaded or did not finish, and how long it took.

By default, a server that cannot be connected does not stop the run. The run
goes on **without** that server's tools, and a warning in the conversation (a
`Warning:` line in the CLI) names the server and why it failed. A server that
drops during the run is reconnected once; if that fails, the tool call returns
an error and the run continues.

## A server the tests need

Some tests are meaningless without their server: a test that reads tickets
from an issue tracker, for example. Mark such a server as required, so a run
stops at once instead of running every test without its tools.

1. Open **Extending → MCP Servers**.
2. Click the pencil next to the server.
3. Clear **Runs go on without this server when it cannot be connected**.
4. Click **Edit server**.

The row now shows **required for runs**. In `utils/mcp.json` the server gets
`"ignoreFailure": false`. Without the key, a run goes on without the server.

When a required server cannot be connected, the run does not start:

- **Conversation**: the server's line in **Surface setup** did not finish, and
  the error names the server, its URL, the reason, and what to check.
- **Tests**: none ran. Each is listed as not run, "because the Extending
  settings could not be loaded".
- **Device**: released again, so the next run can use it.
- **CLI**: exit code `3`, a configuration error, with the same message.

## Edit a server

Click the pencil next to a registered server to change its **Name**, **URL**,
**Headers**, or whether runs go on without it. The dialog opens with the current values; **Edit server**
saves them and checks the connection again, **Cancel** leaves the server as
it was. Editing keeps the server's on/off state.

## Remove a server

Click the trash icon next to a registered server. A confirmation opens,
because removing a server can't be undone: **Delete** removes it from
`utils/mcp.json`, **Cancel** (or **Escape**) keeps it. The rest of the app
stays unavailable until you choose.
