A physical Android phone or tablet is discovered automatically and turned
into a profile with one click, from the Add-device dialog or from the
**Android devices** list on the Devices page.

**Preconditions:** Developer options and **USB debugging** enabled on the
device; connected via USB (accept the debugging prompt on the phone), or
reachable wirelessly.

## Create it

1. Plug the device in.
2. **Add device** → **An Android device**. The dialog lists the phones this
   computer can see, and says what to fix when it sees none, use the rescan
   button after you fixed it.
3. Optionally fill in **Name**, **Description** and **Prompt** above the
   list, the same fields every other kind has; an empty name means the
   phone's model.
4. Click **Add as device** next to the phone, the device becomes a regular
   profile card, bound to its serial, and the dialog closes.

The same phone also appears under **Android devices** on the
[Devices](/docs/devices) page, where **Details** shows what was discovered
(model, Android version, state) and **Add as device** does the same thing.

## Run it

1. **Connect** the profile card.
2. Pick the profile in the test's **Run on** dropdown and press **Run**.

Keep the device awake and unlocked during runs, the agent acts on the real
screen.

## Wireless

No USB: enable wireless debugging on the device, then enter its `ip:port` in
the Wi-Fi field of the Add-device dialog, or in the field next to **Connect
wireless** on the Devices page. The device joins the list and can be added as
a profile the same way.

A device shown as `offline` or `unauthorized` can't be added, reconnect the
cable and accept the debugging prompt on the device.

## No adb on this computer

Talking to a phone needs `adb`, from Google's Android platform-tools. When this
computer has none, the **An Android device** entry of the Add-device dialog lists
no phones and says that this computer needs Google's `adb` tool, and the phone's
row on the Devices page reads **Set up** in place of **Connect**.

**Set up** opens a dialog that installs the platform-tools from Google's own
download, about 15 MB. A phone needs nothing else: no Java, no licence to accept,
no emulator. The dialog shows the progress, can be stopped, and also shows the
manual steps if you prefer to install it yourself. The same install is the
**Android platform-tools** row under **Settings → This machine → Android**. Once
it is there, reopen the Add-device dialog and your phone is in the list.

**An adb you already have counts** — AskUI Desktop uses the first one it finds:
the file `ASKUI_ADB_PATH` names, the platform-tools of the SDK in `ANDROID_HOME`
or `ANDROID_SDK_ROOT`, the Android SDK's default folder, Homebrew's `adb` on a
Mac, `/usr/bin/adb` on Linux, and finally your `PATH`. Then the row shows
**Connect** at once and nothing is installed a second time.

**Removing the platform-tools** — the **Android platform-tools** row has
**Remove** only when AskUI Desktop installed them. Remove disconnects every
connected Android device first, then deletes the platform-tools; phones and
emulators need them again before they connect.
