Tests run on devices: this machine, a browser, a phone. A **device profile**
describes how to reach one. Connected profiles appear in every test's
**Run on** picker, they are your test environments.

| On the page | Meaning |
| --- | --- |
| **Windows Desktop** | This machine's desktop via AgentOS, native applications |
| **Chrome Browser** | A local Chrome window the app launches itself, web tests |
| **Pixel 9** | An Android emulator, created and booted by the app |
| **Connect / Start** | Opens the session. Green dot = ready. Tests only run on connected devices |
| **Probe** | Checks reachability without connecting |
| **Force Restart** (next to Retry, Local profile only) | After a failed Connect: stops the standalone AgentOS controller on this PC and starts a fresh one, see [Remote computer](/docs/devices/remote-computer#restart-the-controller-on-this-pc) |

A new project starts with a **Local** profile (this machine) and, where the
machine supports it, a ready-made **Android Emulator** profile. Deleted
defaults stay deleted.

## Create a profile

1. Click **Add device**.
2. Pick the kind.
3. Enter a name and the kind's fields. The optional **Prompt** field holds
   what the agent gets told about this device on every run, quirks the
   screen doesn't show ("always execute on display 1"). A
   [Multi computer](/docs/devices/multi-computer) or
   [Cross-platform](/docs/devices/cross-platform) profile passes on each
   member's prompt as well, under the member's name.
4. Click **Add device**, then **Connect** the new card.

| Kind | Device | Notes |
| --- | --- | --- |
| [**Remote computer**](/docs/devices/remote-computer) | Any machine running [AgentOS](/docs/agentos), host, port, display | Test on a dedicated machine instead of your own |
| [**Web browser**](/docs/devices/web-browser) | Local browser session, Chromium, Firefox, or WebKit | Optional start URL, headless |
| [**Android emulator**](/docs/devices/android-emulator) | Virtual device on this machine | **An Android emulator** in the dialog; device type + Android version, created on first Start |
| [**iOS simulator**](/docs/devices/ios-simulator) | Apple simulator | macOS only, greyed out on Windows |
| [**Multi computer**](/docs/devices/multi-computer) | Several desktops, one agent | The test names the machine per step ("on the server …, on the client …") |
| [**Cross-platform**](/docs/devices/cross-platform) | Desktop + Android + web in one profile | Connect/status only, runs not supported yet |
| [**Android phone**](/docs/devices/android-phone) | A physical device via USB or wireless | **An Android device** in the dialog lists the phones `adb` sees, **Add as device** adds one; also from the **Android devices** list below |

Each kind has its own page with the exact fields and setup.

## What a device needs on this computer

Every device row says whether this computer has what the device needs. The
button where **Connect** or **Start** sits reads one of four things:

**Checking…** — AskUI Desktop is still looking for the device's tools, for a
moment after the page opens.

**Set up** — something is missing. The dialog lists the device's setups in the
order they install, installs the next one with one click, and shows the manual
steps with the exact commands if you prefer to do it yourself. Nothing downloads
before you click.

**A reason instead of a button** — the device cannot run on this computer, for
example an iOS simulator in a Project opened on Windows.

**Connect** or **Start** — everything is there.

What each kind needs on this computer:

**Web browser** — the browser build of its engine (Chromium, Firefox or WebKit),
downloaded once and shared by every Project.

**This computer's desktop** — [AgentOS](/docs/agentos).

**Android phone** — `adb`, from Google's Android platform-tools, see
[Android phone](/docs/devices/android-phone#no-adb-on-this-computer).

**Android emulator** — the platform-tools and the Android SDK, see
[Android emulator](/docs/devices/android-emulator).

**iOS simulator** — Xcode and `idb_companion`, on a Mac, see
[iOS simulator](/docs/devices/ios-simulator).

The same setups have their own rows under **Settings → This machine**, one card
per kind of device: **Web**, **Computer**, **Android** and **iOS Simulators**.
**Set up** there installs the same thing the device row does, and a setup
started in one place shows its progress in the other. **Remove** appears only
for what AskUI Desktop installed itself; a tool you installed yourself is never
removed.

## Android devices (discovery)

The **Android devices** section lists what `adb` sees: USB-connected phones
(USB debugging enabled) and already-running emulators. **Add as profile**
turns a discovered device into a regular profile, see
[Android phone](/docs/devices/android-phone). For a wireless device, enter
its `ip:port` and click **Connect wireless**. Without `adb` the list stays
empty; the Add-device dialog's **An Android device** entry says so, and
**Settings → This machine → Android** installs it.

## How a test picks its device

The test names its target ("Run this on the **Windows Desktop** device");
the **Run on** picker confirms it. Pick a different connected profile to run
the same test on another environment.

## It uses your mouse and keyboard

A desktop run on this machine is a real user session: the agent moves the
pointer, types, and needs the application in the foreground. Don't work on
the machine during a run, use a browser, emulator, or remote profile to
keep working.

## Where profiles live

`devices.json` in the project, including each profile's **Prompt** text
(and, for a Multi computer or Cross-platform profile, each member's).
Colleagues get the same device list and only connect. See
[How a Project is organized](/docs/projects).
