A **Cross-platform** profile bundles a desktop, an Android device, and a web
browser into one profile, for scenarios that will span all three (start a
flow on the phone, finish it on the desktop).

<Callout type="warn" title="Runs not supported yet">
The profile connects and reports the status of each surface, but running
tests against it is not supported yet. Until it is, split the scenario across
single-surface profiles and run the parts separately.
</Callout>

## Create it

1. **Add device** → **Cross-platform**.
2. Tick the surfaces to combine (at least two) and pick the existing profile
   each one is built from: a Remote computer, an Android device or emulator,
   a Web browser.
3. **Add device**: then **Connect** to see all three surfaces' status.

Each surface is a copy of the profile you picked: its connection details,
its name and its **Prompt**. The profile's own **Prompt** field is for what
the surfaces share; the agent gets it first, then each surface's prompt under
the name of the profile it came from (`Desktop "QA machine": …`,
`Android "Pixel": …`, `Browser "Chromium": …`). A surface whose profile has
no prompt adds nothing.

Editing a source profile later doesn't change the copy: open the Cross-platform
profile again and save it to pick the change up. It remembers which device each
surface was built from, so re-saving keeps the same three devices even when you
have several computers, phones or browsers.
